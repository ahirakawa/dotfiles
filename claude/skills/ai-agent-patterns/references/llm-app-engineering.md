## 「評価が難しい」はプロダクト設計の欠陥シグナル（Hamel Husain）

Sources:
- https://hamel.dev/blog/posts/eval-smell/

### コア主張

- 「このAI出力はevalしにくい」という状況は、ユーザーにとっても検証しにくい出力だということ。eval困難性はプロダクト設計の smell である
- 評価設計と良いプロダクト設計は本質的に同じ。ユーザーが検証できる形に設計すれば自動評価も容易になる

### 事例と解決パターン

- AIデータエージェント: 「純収益は421万ドル」と数値だけ返す→メトリック定義の出典、中間計算ステップ、検証不能項目のフラグを表示する設計へ
- カリキュラム生成: 全体を新規生成して丸ごと判定させる→検証済みの計画を基盤にAIの変更差分だけを表示
- 医療報告書生成: 50ページの意見書を丸ごと再検証→「研究助手」パターンに転換し、各事実に文献リンク付きの出典を提示

### 検証設計の4つの問い

- ユーザーが実際に何を確認する必要があるか / 信頼できる比較対象は何か / ドメイン専門家が使う検証シグナルは何か / ユーザーが受け入れ・編集・却下できる単位は何か
- **教訓**: text-to-SQL やデータエージェントを作るなら「答えの数値」ではなく provenance（出典・中間ステップ）を返す設計にする。eval しにくいと感じたら evals を頑張る前にプロダクト側を疑う
