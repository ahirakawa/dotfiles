# 落とし穴カタログ

セッションで実際に踏んだ罠を1件ずつ追記して育てる。Fable 利用期間中は特に、Fable が回避した判断分岐を見つけたら記録する（/retrospective-codify が使える場面ならそちら経由でここに落とす）。

形式: 状況 / 兆候 / やりがちな誤り / 正しい対処 / 記録日。

## エントリ

### 検証の後回し
- 状況: 複数ファイルの変更を一気に進めている
- 兆候: 「あとでまとめてテストしよう」と考え始める
- やりがちな誤り: 最後に検証してエラーが複数原因で絡まり、切り分けに時間を溶かす
- 正しい対処: チェックポイントごとに検証し、エラーは1変更分の範囲で切り分ける
- 記録日: 2026-07-09（初期シード）

### パターン一致による誤診
- 状況: 既知の障害と似たシグナルが出た
- 兆候: ログや症状が過去のケースと「似ている」ことだけを根拠に対処を始めようとしている
- やりがちな誤り: 別原因の症状に過去の対処（再起動・設定変更）を適用して状態を悪化させる
- 正しい対処: 対処の前に、その操作を支持する証拠を今回のケースで確認する
- 記録日: 2026-07-09（初期シード）
